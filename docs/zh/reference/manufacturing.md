# 量产与设备标识的生命周期

批量把 Mica OS 装到设备上的规则：工厂消耗什么、必须校验什么、记录什么，以及如何处理失败或返修的设备而从不
克隆标识。面向集成方的指南是[量产](../integrate/manufacturing.md)。

## 1. 今天有什么

**Mica OS 不提供工厂工具。**工厂可依托的是：

- 首次启动的自我配置：设备在首次启动时自己生成设备 id、主机名和秘密，从不放在镜像中
  （[配置](../../integrate/provisioning.md)）；
- 用于第一份配置的配置文档或产品种子（[配置](../../integrate/provisioning.md)第 4 和第 6 节）；
- 每块板卡带回读的整盘写入，作为刷写和恢复的基本手段（[板卡页面](../hardware/README.md)）；
- `GET /api/v1/system/info`，让工位查询刷写好的设备的部署，以及它信任生产密钥还是开发密钥。

下面的一切是工厂工作要遵循的契约。其中没有任何一项是这些仓库里的工具。

## 2. 输入有版本

工厂消耗的每项输入都有版本，一经发出即不可变，并在每台设备的记录中写明。由无版本输入构建的设备无法审计、
无法按批次召回，也无法复现。

| 输入 | 规则 |
|---|---|
| 发布镜像 | 一个有名称、已签名的发布，从不是零散构建；信任开发密钥的镜像从不在工位上刷写（[签名](../security/signing.md)） |
| 序列号和 MAC 地址 | 以有界的分配发放；一个值只消耗一次，从不归还到池中 |
| 校准数据 | 由有版本的工位产生；工位版本是记录的一部分 |
| 标识 | 不是输入：它在设备上生成，由工位见证 |
| 密钥 | 工厂只拿到公开锚点和签名制品；签名私钥留在签名环境中 |

## 3. 不注入未经校验的东西

任何东西都不能只由写入它的工具来校验。

- **镜像**：首次启动之前回读，并与发布公布的摘要比对。
- **序列号和 MAC**：通过运行中的系统回读，并对照分配检查：既要是分配的那个值，又要此前未被消耗过。重复是
  隔离事件，而不是重试。
- **校准**：检查被校准子系统的输出是否在验收界限内，而不仅是写入成功。
- **标识**：工位见证首次启动完成，并记录从设备上读到的设备 id。工位从不提供或复制标识。

## 4. 每台设备一份记录

在第一个工位创建，在通过或隔离时关闭，并在产品的支持期内保存：

- **回读到的**标识（设备 id、序列号、MAC 地址），而不是分配的值；
- 消耗的每项有版本的输入；
- 每个工位的证据：测量值与界限对照，而不只是结论；
- 处置结果：通过，或隔离并注明失败的工位；
- 对返工的设备，从旧标识到新标识的关联。

每一行是通过、失败或未测试，从不默认算作通过（[验收](../hardware/qualification.md)）。

## 5. 隔离、返工与返修

在某个工位失败的设备停止前进。它已消耗的序列号和 MAC 保持已消耗。它离开隔离的方式是返工（新的记录代数），
或报废，报废包括销毁其存储：DATA 未加密（[安全模型](../security/model.md)）。

**一个设备标识在任何时候都只存在于一台物理设备上。**

- 替换的主板获得新标识。全新写入会在首次启动时生成新的设备 id；没有人为了保留标识而把一台设备的状态复制到
  另一台上。连续性在记录中，而不在闪存上。
- 返修设备的凭据从接收起就视为已暴露，与其标识相关的任何信任在那时就撤销，而不是等到诊断时。

## 6. 各生命周期阶段的端口

| 端口 | 工厂 | 现场 |
|---|---|---|
| 串口控制台 | 开放；工位可用它见证配置过程 | 一个任何账户都无法满足的登录提示（[访问](access.md)） |
| SSH 和 API | 工位网络、工位凭据 | SSH 默认关闭；通过运维者登记的密钥访问 |
| 板卡加载器模式 | 刷写的基本手段 | 对物理接触开放：它是恢复路径，也是物理访问的边界 |
| JTAG / SWD | 在台架上开放 | 按板卡和版本记录在板卡的 `evidence.json` 中；当前没有板卡强制关闭 |

因此现场的态势是：软件访问默认关闭并受凭据控制；物理访问按设计开放，并明确说明它就是边界。

## 7. 不可逆的操作

熔断调试端口、锁定启动配置或烧写密钥哈希在大多数 SoC 上不可逆；在恢复路径就是物理端口的设备上，错误的熔断
会毁掉这条路径。

- 任何不可逆操作在进入生产之前，都必须在同一板卡版本的牺牲硬件上验证，包括证明熔断后的设备仍能启动、仍能
  更新、仍有恢复路径，或者记录下接受它没有恢复路径。
- 厂商文档是输入，不是证据。
- 在一块板卡具备这样的验证之前，Mica OS 不为它提供熔断的调试或启动策略，也不声称高于
  [保证等级](../hardware/assurance.md)中软件层级的任何东西。
